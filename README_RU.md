# Полная копия исходного проекта Elizi Studio

Это точный экспорт 213 отслеживаемых файлов исходного проекта, без изменения HTML, CSS, JavaScript, изображений или настроек. Действующий сайт не изменён, новая версия не опубликована.

Источник: https://elizistudio-portfolio.cleverboot18.chatgpt.site/
Версия Sites: 42
Commit: fcf57b11d0834e7d0c59154606ab0262ae292563

## Состав

- `dist/` — полный готовый статический сайт: HTML, CSS, JavaScript, изображения, favicon и webmanifest. Здесь находятся и исходники: у сайта нет отдельной сборки или серверной части.
- `.openai/hosting.json` — оригинальные настройки размещения Sites; сохранены для полноты, GitHub Pages их не использует.
- `EXPORT_SHA256.json` — контрольные суммы всех 213 оригинальных файлов.
- `.github/workflows/pages.yml` — добавленная отдельно инструкция автоматической публикации папки dist на GitHub Pages; не является частью оригинального проекта. Запускается только вручную.
- `.gitignore` — добавлен для исключения локального мусора.

Сохранены все файлы изображений из исходного репозитория, включая неиспользуемые. Служебный каталог .git и временные файлы среды разработки не включены; паролей и токенов в экспорт не добавляли. История Git не входит в ZIP.

## Важное ограничение: шрифты

В оригинальном style.css Mazzard H Regular и Kunstler Script Regular подключены через local(), без файлов WOFF/WOFF2/TTF/OTF. Поэтому в архиве нет файлов этих шрифтов: их не было в исходном проекте. Сохранены точные CSS-объявления. Если на устройстве шрифты не установлены, браузер использует запасные sans-serif и cursive, как и на текущем сайте. Полностью одинаковую типографику на всех устройствах этот экспорт не гарантирует. Для встраивания позже понадобятся оригинальные файлы и право на веб-использование. Никакие шрифты не заменялись и не подбирались приблизительно.

## Локальный запуск

Установите Python 3. В терминале из корня распакованного проекта выполните:

```sh
python3 -m http.server 8000 --directory dist
```

На Windows при необходимости:

```sh
py -m http.server 8000 --directory dist
```

Откройте http://localhost:8000 . Для остановки нажмите Ctrl+C. Node.js, npm и сборка не требуются. Внешние ссылки Telegram, Behance и почты сохранены; сервер базы данных и ключи API не нужны.

## Перенос на GitHub Pages

1. Создайте новый публичный репозиторий в своём аккаунте GitHub. Для корневого адреса имя репозитория должно быть ТОЧНО `ВАШ_ЛОГИН.github.io`. Для другого имени адрес будет `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.
2. Распакуйте ZIP. Загрузите СОДЕРЖИМОЕ папки `elizistudio-source`, сохраняя все вложенные папки, включая `.github`. Не загружайте ZIP как единственный файл. Для большого количества файлов удобнее GitHub Desktop или Git.
3. В репозитории откройте Settings → Pages → Source → GitHub Actions.
4. Откройте Actions → Deploy exported portfolio to GitHub Pages → Run workflow. Выберите нужную ветку и запустите вручную.
5. После успешного выполнения адрес появится в Settings → Pages и в результате workflow.

Workflow имеет только workflow_dispatch: обычная загрузка файлов сама по себе не публикует сайт. В этом экспорте никакой репозиторий GitHub не создан и никакая публикация не выполнялась. Не удаляйте старый сайт до проверки новой копии.

## Проверка после переноса

Сравните desktop и mobile, загрузку изображений, фильтры портфолио, открытие/закрытие проектов, анимацию brand/graphic designer, курсор на ПК, переходы по стрелке и контакты. Проверьте доступ без VPN на Wi-Fi и мобильной сети. Доступность GitHub Pages в конкретной сети заранее не гарантируется.

Старый адрес не переезжает автоматически: новый хостинг выдаёт новый URL. Описание и заголовок превью сохранены, но мессенджеры могут кешировать прежние данные. Настройки доступа и защиту домена chatgpt.site перенести на GitHub невозможно; они принадлежат платформе, а не коду сайта.
